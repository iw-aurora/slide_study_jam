01 · The problem

Vì sao cần quản lý phiên bản?

Hãy tưởng tượng cả nhóm cùng sửa một project nhưng không có cách ghi lại lịch sử thay đổi.

Vấn đề 01

Mất dấu thay đổi

Không rõ ai sửa file nào, sửa lúc nào và vì sao.

Vấn đề 02

Khó quay lại

Bản mới bị lỗi nhưng không có phiên bản cũ đáng tin để khôi phục.

Vấn đề 03

Khó làm việc nhóm

Nhiều người sửa cùng project dễ ghi đè hoặc xung đột code.

Version Control giúp trả lời: đã thay đổi gì, khi nào, bởi ai và có thể quay lại đâu?

02 · Git

Git là gì?

Git là hệ thống quản lý phiên bản phân tán (Distributed Version Control System – DVCS), dùng để theo dõi thay đổi trong file và mã nguồn.

Theo dõi lịch sử

Mỗi lần commit tạo một mốc lưu thay đổi có thể tra cứu và so sánh.

Phát triển song song

Branch cho phép thử nghiệm tính năng độc lập với nhánh chính.

Làm việc phân tán

Mỗi người có bản sao repository và lịch sử trên máy của mình.

Tích hợp thay đổi

Merge kết hợp công việc; conflict cần được giải quyết khi thay đổi không tương thích.

03 · Version control systems

Ngoài Git còn có gì?

Các hệ thống quản lý phiên bản có thể được chia thành hai hướng chính.

Centralized · CVCS

Subversion (SVN)

Có máy chủ trung tâm lưu lịch sử. Người dùng checkout và commit thay đổi lên server.

Distributed · DVCS

Git / Mercurial

Mỗi bản sao repository có lịch sử phiên bản. Có thể commit và xem lịch sử khi offline.

04 · GitHub

GitHub là gì?

GitHub là nền tảng lưu trữ repository Git và cung cấp công cụ để cộng tác phát triển phần mềm.

Repository

Nơi lưu mã nguồn và lịch sử commit của dự án.

Pull Request

Đề xuất đưa thay đổi vào nhánh khác, thường kèm review.

Issues

Ghi nhận bug, yêu cầu tính năng và công việc.

Actions

Tự động hóa kiểm thử, build và quy trình CI/CD.

Projects

Theo dõi tiến độ và tổ chức công việc nhóm.

Code Review

Thảo luận và kiểm tra chất lượng thay đổi trước khi tích hợp.

Git ≠ GitHub
Git là công cụ quản lý phiên bản; GitHub là một nền tảng cộng tác sử dụng Git.

06 · Git internals

Git quản lý code qua những khu vực nào?

Luồng cơ bản từ file đang sửa đến lịch sử commit:

01

Working Directory

File trên máy, nơi ta chỉnh sửa code.

→
02

Staging Area

Chọn thay đổi sẽ đưa vào commit.

git add
→
03

Local Repository

Lưu commit và lịch sử trên máy.

git commit

Remote Repository

Bản repository ở máy chủ từ xa, ví dụ GitHub. Dùng git push để gửi commit lên remote; dùng git fetch/git pull để lấy thông tin và thay đổi từ remote.

07 · File lifecycle

Vòng đời trạng thái của một file

UntrackedFile mới, Git chưa theo dõi.
UnmodifiedFile đã được theo dõi, hiện chưa có thay đổi so với phiên bản đã commit.
ModifiedFile đã được chỉnh sửa kể từ lần commit gần nhất.
StagedThay đổi đã được đưa vào Staging Area, sẵn sàng commit.

Ví dụ với file index.html

Tạo index.html → Untracked git add index.html → Staged git commit -m "..." → Unmodified Sửa nội dung file → Modified git add index.html → Staged git commit -m "..." → Unmodified

Một file có thể chuyển qua lại giữa Modified và Staged nhiều lần trước khi commit.

10 · Wrap-up

Điều cần nhớ

① Git theo dõi lịch sử thay đổi của mã nguồn.

② GitHub lưu trữ repository Git và hỗ trợ cộng tác.

③ add → commit → push là luồng cơ bản để lưu và chia sẻ thay đổi.

④ Branch → Pull Request → Review → Merge giúp nhóm phát triển an toàn hơn.

Git không chỉ giúp lưu code — nó giúp cả nhóm làm việc có lịch sử, có quy trình và có thể phối hợp.
