01 · The problem

Vì sao cần quản lý phiên bản?

Hãy tưởng tượng cả nhóm cùng sửa một project nhưng không có cách ghi lại lịch sử thay đổi.

Vấn đề 01

Mất dấu thay đổi

Không rõ ai sửa file nào, sửa lúc nào và vì sao.

Vấn đề 02

Khó quay lại

Bản mới bị lỗi nhưng không có phiên bản cũ đáng tin để khôi phục.

Vấn đề 03

Khó làm việc nhóm

Nhiều người sửa cùng project dễ ghi đè hoặc xung đột code.

02 · Git

Git là gì?

Git là hệ thống quản lý phiên bản phân tán (Distributed Version Control System – DVCS), dùng để theo dõi thay đổi trong file và mã nguồn.

Theo dõi lịch sử

Mỗi lần commit tạo một mốc lưu thay đổi có thể tra cứu và so sánh.

Phát triển song song

Branch cho phép thử nghiệm tính năng độc lập với nhánh chính.

Làm việc phân tán

Mỗi người có bản sao repository và lịch sử trên máy của mình.

Tích hợp thay đổi

Merge kết hợp công việc; conflict cần được giải quyết khi thay đổi không tương thích.

04 · GitHub

GitHub là gì?

GitHub là nền tảng lưu trữ repository Git và cung cấp công cụ để cộng tác phát triển phần mềm.

Repository

Nơi lưu mã nguồn và lịch sử commit của dự án.

Pull Request

Đề xuất đưa thay đổi vào nhánh khác, thường kèm review.

Issues

Ghi nhận bug, yêu cầu tính năng và công việc.

Actions

Tự động hóa kiểm thử, build và quy trình CI/CD.

Projects

Theo dõi tiến độ và tổ chức công việc nhóm.

Code Review

Thảo luận và kiểm tra chất lượng thay đổi trước khi tích hợp.

Git ≠ GitHub
Git là công cụ quản lý phiên bản; GitHub là một nền tảng cộng tác sử dụng Git.

Repository · Pull Requests · Pipelines · Jira

Nguồn ảnh ↗
GitHubRepository và cộng tác cộng đồng; nổi bật với Issues, Pull Requests, Actions.
GitLabWorkflow DevOps tích hợp từ planning, code đến CI/CD.
BitbucketTích hợp chặt với Jira và công cụ Atlassian.

Ngoài ra còn có Gitea (self-host nhẹ) và Codeberg (hướng đến phần mềm tự do). Git là VCS; GitHub, GitLab và Bitbucket là nền tảng hosting/cộng tác.

Ảnh giao diện tham khảo; UI có thể thay đổi theo phiên bản.

07 · File lifecycle

Vòng đời trạng thái của một file

File lifecycle · Trạng thái và thao tác
📄

Untracked

File mới — Git chưa theo dõi.

git add→
📦

Staged

Đã chọn thay đổi để commit.

git commit→
✅

Unmodified

Không khác snapshot đã commit.

→
✏️

Modified

File đã được chỉnh sửa.

git add
Modified ── git add ──→ Staged ── git commit ──→ Unmodified

Sửa file từ Unmodified sẽ chuyển sang Modified; file có thể quay lại Staged nhiều lần trước khi commit.

Sau khi commit, file trở về Unmodified. Khi sửa tiếp, file chuyển sang Modified và có thể được add lại nhiều lần.

09 · Useful commands

Một số lệnh Git nên biết

LệnhCông dụng
git initKhởi tạo repository Git mới.
git clone URLSao chép repository từ remote về máy.
git statusXem trạng thái file và working tree.

10 · Wrap-up

Điều cần nhớ

① Git theo dõi lịch sử thay đổi của mã nguồn.

② GitHub lưu trữ repository Git và hỗ trợ cộng tác.

③ add → commit → push là luồng cơ bản để lưu và chia sẻ thay đổi.

④ Branch → Pull Request → Review → Merge giúp nhóm phát triển an toàn hơn.

Git không chỉ giúp lưu code — nó giúp cả nhóm làm việc có lịch sử, có quy trình và có thể phối hợp.
